# 1. Project setup

This repo is already a Next.js app (see [README](README.md)). These steps add the database on top.

## Install dependencies

These guides use **Prisma 6**. It keeps the classic `prisma-client-js` generator and `url = env("DATABASE_URL")` in the schema. Prisma 7 moved the connection URL into `prisma.config.ts` and needs a driver adapter. If you upgrade later, follow Prisma's v7 upgrade guide.

```bash
npm install @prisma/client@6
npm install -D prisma@6
```

Optional, only for [04-payments.md](04-payments.md):

```bash
npm install stripe
```

## Local Postgres

Pick one.

**Homebrew (macOS):**

```bash
brew install postgresql@17
brew services start postgresql@17
createdb nebula
```

**Docker** (add `docker-compose.yml` at the project root):

```yaml
services:
  db:
    image: postgres:17
    restart: unless-stopped
    environment:
      POSTGRES_USER: nebula
      POSTGRES_PASSWORD: nebula
      POSTGRES_DB: nebula
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data
volumes:
  pgdata:
```

```bash
docker compose up -d
```

**Hosted:** create a free database on Neon, Supabase or Vercel Postgres and copy the connection string.

## Environment variables

`.env` (do not commit — `.gitignore` already ignores `.env*` except `.env.example`):

```bash
# Homebrew: postgresql://<your-mac-username>@localhost:5432/nebula?schema=public
# Docker:   postgresql://nebula:nebula@localhost:5432/nebula?schema=public
DATABASE_URL="postgresql://nebula:nebula@localhost:5432/nebula?schema=public"

# Leave empty: the forms call same-origin /api routes.
NEXT_PUBLIC_API_URL=

# Optional — 04-payments.md
STRIPE_SECRET_KEY=
STRIPE_WEBHOOK_SECRET=
SITE_URL=http://localhost:3000
```

Add the same keys, with empty values, to `.env.example` (it already has `NEXT_PUBLIC_API_URL`).

> Prisma CLI reads `.env`. Next.js reads both `.env` and `.env.local`. Keep `DATABASE_URL` in `.env` so both see it.

## Initialise Prisma

```bash
npx prisma init --datasource-provider postgresql
```

This creates `prisma/schema.prisma`. If `prisma init` also writes a `.env`, merge it with the one above. Then replace the schema with the one in [02-database.md](02-database.md).

## package.json scripts

```json
{
  "scripts": {
    "dev": "next dev",
    "build": "prisma generate && next build",
    "start": "next start",
    "lint": "eslint",
    "postinstall": "prisma generate",
    "db:migrate": "prisma migrate dev",
    "db:deploy": "prisma migrate deploy",
    "db:reset": "prisma migrate reset",
    "db:studio": "prisma studio"
  }
}
```

`postinstall` makes sure the client is generated on CI and Vercel, where `node_modules` is cached.

## Target folder layout

New files are marked with `+`. Nothing outside `prisma/`, `src/app/api/` and `src/lib/` changes.

```
nebula/
├─ prisma/                          +
│  ├─ schema.prisma                 +
│  └─ migrations/                   + (generated by prisma migrate)
├─ public/
├─ src/
│  ├─ app/
│  │  ├─ (pages — already there)
│  │  └─ api/                       +
│  │     ├─ contact/route.ts        +
│  │     ├─ newsletter/route.ts     +
│  │     ├─ payments/route.ts       +
│  │     └─ stripe/webhook/route.ts + (optional, 04-payments.md)
│  ├─ components/                   ← unchanged
│  └─ lib/
│     ├─ api.ts                     ← browser client (already there, unchanged)
│     ├─ contracts.ts               ← shared types + validators (already there, unchanged)
│     ├─ prisma.ts                  + Prisma client singleton
│     ├─ http.ts                    + JSON responses, body parsing, rate limit
│     └─ stripe.ts                  + (optional)
├─ .env                             +
├─ .env.example                     ← add the new keys
└─ docker-compose.yml               + (if using Docker)
```
